# Analytics view

- **Analytics view** (`views/AnalyticsView.vue`, route `/analytics`, **lazy-loaded** to keep Chart.js out of the main chunk). Everything is computed client-side from the flights store by pure functions in `src/analytics.ts` (same reasoning as `flightCounts.ts`), plus one `getAirportsByCodes` call for countries and city names — no new backend.
  - **Filter-aware via the shared `filters.ts` model**, like Flights and Map: the route query filters what is counted, chips are removable, and "View in log" / "View on map" carry the query across. The **Period** picker (`NcSelect`) *is* a `dateFrom`/`dateTo` filter spanning exactly one calendar year (`yearOfRange` / `yearRange`); while it shows such a year the date chip is hidden, and any other range shows its chip and a "Custom date range" entry. Year options are counted over the flights matching every filter *except* the date.
  - **Everything countable drills through to the log** with its own filter merged over the current query (`logLink`; a key set to `undefined` is *removed*, so a click replaces a filter of its kind rather than inheriting half of it). Ranked rows, legend rows and record cards are links: `airline`, `airport`+`airportDir=either`, `aircraft` by `aircraftDisplay`, `manufacturer` (the "Other" slice sends all of its manufacturers as one CSV), `cabin`, route for the most-flown route, `flight` for longest/shortest, `registration` for the most-flown airframe. Chart elements emit `select` from `BarChart`/`DonutChart` (only when `clickable`, and never for an empty bar; pointer cursor + a "Click to see these flights" tooltip footer): a per-period column → that month or year as `dateFrom`/`dateTo`, **narrowed to any date filter already set** (`narrowToDateFilter` in `filters.ts`) — the column only counted flights inside the chip, so a custom range cutting through the month or year must not be widened back to the whole period, a weekday → `weekday`, a distance bin → `distanceMin`/`distanceMax` (the bin's own bounds; a bin's lower bound is inclusive, so the last one reads "≥ 8,000 km", not "> 8,000"), a cabin slice → `cabin`. Every one is keyed by exactly the value its filter matches, so an element's count equals what its drill-through returns — pinned by tests that run each row, bin and weekday back through `buildFilters`. Canvas clicks have no keyboard path; the hidden data tables are text only, so a keyboard user filters via the Flights view's `FilterPicker`.
  - **Year-on-year deltas** appear only when a single year is selected and the previous year has flights. For the *current* year both sides are cut at today's month-day (`comparisonPeriod`, "vs 2025 to date"), so January is not compared with a whole year.
  - **Definitions** (in `analytics.ts`, change them there): legs with no `distance_km` still count as flights but add nothing to distance, and a footnote (shown only when there are any) says how many. There is deliberately no flight-hours figure: the journal stores no times, and an estimate from distance (tried: 30 min/leg + 830 km/h) was removed as not worth showing. The per-period charts are single-series — a short/medium/long-haul stacking was tried and removed as noise. Weekdays come from the date's calendar parts (`dateParts`), never `new Date('YYYY-MM-DD')`, which is UTC midnight and shifts a weekday west of Greenwich.
  - **Canvas vs HTML split.** Chart.js (`vue-chartjs`) draws the per-period columns, the distance histogram, the weekday polar-area chart (`PolarChart.vue`, matching tickbuddy's "Days of week" in size — 260px tall — and tones: radius and shade both follow the count, each slice taking the page palette step nearest its position between the fewest and the most. Labels sit outside the ring as "Mon **34**" on one line, so no value is tooltip-only, with padding derived from the same constants the labels are drawn with) and the cabin and manufacturer doughnuts (the doughnuts via `DonutBreakdown.vue`, which pairs the ring with its linked legend; manufacturers show the top three plus an "Other" slice, shaded by rank because they have no natural order — largest on palette step 5, then 4, then 3 — with "Other" in neutral grey; cabin classes have fixed steps, economy 2 … first 5) (`components/analytics/BarChart.vue` — single-series by design — and `DonutChart.vue`); tiles, ranked lists (`RankedList.vue`), records and the Earth/Moon figures are HTML, because they need real links and readable labels. Airport rows put the code in the label text ("FRA · Frankfurt-am-Main") rather than a separate badge. Tooltips use a registered `'cursor'` positioner (`chartPlugins.ts`) so the box follows the pointer instead of pinning to the bar. Every bar carries a value label (`chartPlugins.ts` → `valueLabels`) so no number is tooltip-only; when a column chart is too narrow for its labels (phone width), `BarChart` measures itself and swaps labels for a value axis rather than let them overlap. Each canvas also renders a visually hidden data table.
  - **Theming** (`src/chartTheme.ts` + `src/colorRamp.ts`) follows the nextcloud `charts` skill: colours are read from `document.body` (an explicitly chosen theme lives on `body[data-theme-*]`, not `:root`); **one palette for the whole page** (`theme.palette`): the solid primary at `PALETTE_OPACITY` 20 / 36 / 53 / 69 / 85% (tickbuddy's polar range, evenly stepped), each computed as the opaque colour that opacity shows over the page background (`blend`), not an rgba fill, so HTML swatches match the canvas and contrast stays measurable. Every slice of every sliced chart (both doughnuts, the weekday polar chart) takes one of those five — per-chart ramps were tried and dropped because two doughnuts side by side came out in visibly different blues. The pale steps are below the 2:1 an unoutlined fill needs, so **every sliced chart outlines its slices with a 1px solid primary line** (`primarySolid`). Single-series fills (bars, ranked bars, rings, meter) are step 4 (`FILL_OPACITY`), raised only for a pale accent so they never drop below 3:1 (`soften`), and a hovered bar is drawn at full strength. "Other"/"No data" are a neutral grey, outside the palette. The theme ref re-reads on OS scheme/contrast changes. The colours are exposed to the HTML as `--fj-chart-primary`, `--fj-chart-neutral` and `--fj-palette-1…5`. The palette passes the dataviz ordinal checks (monotone, ΔL ≥ 0.06, one hue) on all four stock themes; a few extreme accents near Nextcloud's 3.2:1 floor (bright yellow/lime/cyan on light, dark navy on dark) bunch the steps closer than ΔL 0.06.
  - **Ranked lists show at most 6 rows** — `RankedList`'s default, used unchanged by Airlines, Airports, Aircraft types and routes, so the lists line up; don't pass a per-list `limit`.
  - **Top routes**, under one heading (no count beside it) with two charts (chosen after trying a by-flights bubble chart and an all-routes scatter). *By number of flights*: a `RankedList` styled like Airlines/Airports and capped like every ranked list at its default 6 rows — label on top, thin bar, count, each row a link (`rankRoutes`, both directions combined, keyed exactly like the `routeDir=both` filter; a list row needs no distance, so every route qualifies). *By distance flown*: the top 8 (`TOP_ROUTES_BY_DISTANCE`, deliberately more than the lists) by distance flown (`rankRoutesByDistanceFlown`: `RouteStat.totalKm`, the sum of the legs' own distances — flights × distance when every leg has one; a leg without a distance adds nothing, as in the summary tile, while the bubble's size still counts every leg so it matches the route's drill-through) as bubbles (`BubbleChart.vue`) — one 35px row per route, x = distance, bubble **area** ∝ flights (`r ∝ √count`), the distance flown written beside each bubble (`BubbleRow.note`), a caption explaining the ranking, and a footnote counting routes left out for having no distance. The bubble y-axis sets its own ticks in `afterBuildTicks`, one per row; left to Chart.js they land between rows and every label comes out blank. Both drill to the route on click.
  - **Page layout is a stack of rows**, each either full-width or two equal columns (the shared `.grid`: `1fr 1fr`, collapsing to one column below 900px — every two-column row uses it, which is what keeps the columns aligned down the page). Top to bottom: summary tiles (full) · flights | distance per period · Top routes: by number of flights | by distance flown · Distance in context (Earth circumferences and Earth–Moon stacked in one cell) | Distance distribution · Airlines | Airports · Aircraft: manufacturers | types · Cabin class | Days of week · Records (full) · footnote (full). Two related charts share one full-width `h3` with `h4` subheadings and a muted count beside each (`.block` > `.block__head` + `.grid` of `.cell`s with `.cell__head`) — the per-period row ("Flights and distance per year": Number of flights | Distance flown), Top routes (By number of flights | By distance flown) and Aircraft (Manufacturers | Types); unrelated neighbours each carry their own `h3`. A new chart goes into a two-column row, never a one-off column split. **Every half of a two-column row is a heading followed by one `.cell__body`**: the grid stretches both halves to the taller one's height, the body fills what's left under the heading and centres its content vertically, so headings stay level across the row while a short chart beside a long list sits in the middle instead of leaving its space at the bottom (pinned by a test that checks every half).
  - Not built yet: a `FilterPicker` on this view (it hard-codes navigation to `flights`, so it would need to push to the current route), airline names (the `flightjournal_airlines` table exists but nothing populates it — the Airlines list shows codes), and `FilterPicker` editors for the four drill-only filters (weekday, distance, manufacturer, registration — reachable today only from Analytics, though their chips work everywhere).
